PurposeThis document is the implementation specification for the CSE 576 class project **Project C: Training-free, Budget-aware Retriever**.The project investigates whether a pretrained small language model (SLM) can act as a **training-free, query-conditioned controller for adaptive multi-hop traversal over a chunk-level document graph**.The implementation will build on **SAGE (Structure Aware Graph Expansion)** for the document graph and existing retrieval pipeline. The research contribution is **not a new graph-construction method**. The main contribution is an SLM-controlled traversal policy that selectively explores graph neighbors and decides when to stop under a limited retrieval budget.This PRD is intended to keep implementation aligned with the approved project proposal and prevent unplanned changes in research scope.---## 2. Core Research GoalThe central question is:> Can a pretrained SLM guide query-conditioned, multi-hop traversal over a SAGE document graph without task-specific training, while reducing unnecessary graph exploration under a constrained retrieval budget?The system must therefore support measurement of both:1. **Retrieval effectiveness**2. **Retrieval/computational efficiency**The goal is not simply to maximize retrieval accuracy. The project studies the trade-off:**retrieval effectiveness vs. retrieval cost**---## 3. Research Questions### RQ1 — Training-Free Traversal EffectivenessCan a pretrained SLM provide effective query-conditioned guidance for selecting relevant neighboring chunks without training a task-specific graph traversal model?### RQ2 — Adaptive Multi-Hop Retrieval and StoppingCan the SLM determine when additional graph exploration is necessary and when sufficient evidence has already been retrieved?### RQ3 — Budget-Aware RetrievalCan the SLM-controlled traversal maintain retrieval effectiveness while reducing unnecessary graph exploration and inference cost under a fixed computational budget?Implementation decisions should directly support these research questions.---## 4. Scope Boundary### Reuse from SAGEWhere supported by the actual repository, reuse SAGE for:- dataset/corpus loading;- document preprocessing;- semantic chunking;- chunk-level graph construction;- graph storage;- initial query retrieval;- seed-node retrieval;- existing graph expansion/retrieval baseline;- existing evaluation infrastructure where applicable.### Our contributionImplement:- an interface between the SAGE graph and an SLM controller;- candidate-neighbor generation;- optional lightweight candidate pre-filtering;- training-free SLM traversal decisions;- `EXPLORE(node)` / `STOP` actions;- selective multi-hop traversal;- visited-node tracking and cycle prevention;- explicit traversal-budget accounting;- adaptive stopping;- traversal logging;- efficiency evaluation;- comparison against retrieval baselines.### Explicitly out of scope unless approved laterDo **not** independently add:- SLM fine-tuning;- supervised traversal training;- reinforcement learning;- a new graph-construction algorithm;- GraphRAG;- LinearRAG graph construction;- HyperGraphRAG;- multimodal retrieval;- chart/image retrieval;- table retrieval;- multi-agent systems;- web search;- custom knowledge-graph extraction;- custom human annotation;- production UI/dashboard;- unrelated vector-database migrations;- arbitrary LLM-as-a-judge evaluation.---## 5. Initial Seed RetrievalFor query `q`, use SAGE's existing initial retrieval mechanism where feasible to obtain the top-`k` seed nodes:```textS0 = R_k(q)```Where:- `q` = original query;- `R_k` = initial retriever;- `S0` = top-`k` seed-node set.Initialize:```textE0 = S0   # retrieved evidenceV0 = S0   # visited nodesH0 = []   # traversal historyB0 = B    # remaining expansion budget```Do not immediately expand every neighbor for the proposed method.The unvisited graph neighbors become candidates for SLM-controlled traversal.Keep `k` configurable.---## 12. Candidate GenerationAt traversal step `t`, let `N(v)` be the graph neighbors of node `v`.Conceptually:```textNt = union of neighbors of relevant/current evidence     minus already visited nodes```The implementation should avoid cycles by excluding nodes in the visited set.### Important design constraintDo not automatically send an arbitrarily large neighborhood to the SLM.If the candidate set is large, support an optional cheap pre-filter that retains only the top-`m` candidates before SLM reasoning.The exact pre-filter scoring method is **not fixed by this PRD**.Preferred order of decisions:1. inspect whether SAGE already exposes a suitable relevance/reranking score;2. reuse it if appropriate;3. otherwise report alternatives before implementing a new scoring method.Keep `m` configurable.---## 13. SLM Traversal StateAt each traversal step, the controller conceptually receives:```textXt = (q, Et, Nt, Ht, Bt)```Where:- `q` = original query;- `Et` = evidence retrieved so far;- `Nt` = candidate neighboring chunks;- `Ht` = traversal history;- `Bt` = remaining graph-expansion budget.The SLM should receive enough text for each candidate to judge whether it is useful for answering the query.Do not send the entire corpus or entire graph to the SLM.---## 14. Initial SLMInitial candidate model:**Qwen3-4B-Instruct-2507**Local development preference:- 4-bit quantized model;- MLX / `mlx-lm`;- short context containing only relevant traversal state;- deterministic or low-temperature generation;- short structured output;- no task-specific fine-tuning.The controller abstraction must remain model-agnostic so another SLM can be substituted later.Conceptual interface:```pythonclass TraversalController:    def choose_action(        self,        query,        evidence,        candidates,        history,        remaining_budget,    ):        ...```---## 15. Controller Action SpaceFor the initial implementation, the SLM selects **at most one neighboring node per decision**.Allowed actions:```textEXPLORE(node_id)STOP```Conceptually:```textat ∈ {EXPLORE(v) | v ∈ Nt} ∪ {STOP}```Do not initially implement multi-node branching per SLM decision.That can be considered later as an ablation/extension.---## 16. Structured SLM OutputDo not rely on free-form natural language to control traversal.Preferred schema:```json{  "action": "EXPLORE",  "node_id": "node_123"}```or:```json{  "action": "STOP",  "node_id": null}```A short optional rationale may be logged during development:```json{  "action": "EXPLORE",  "node_id": "node_123",  "reason": "This candidate provides evidence needed for the second hop."}```The algorithm must **not depend on the rationale**.Only the structured action controls traversal.---## 17. Invalid SLM OutputThe system must safely handle:- malformed JSON;- empty output;- invalid action;- nonexistent node ID;- node outside the supplied candidate set;- already visited node;- multiple conflicting actions.Invalid output must not crash the experiment.Use deterministic fallback/error handling and log the event.Do not silently reinterpret ambiguous output.---## 18. EXPLORE TransitionIf the controller returns:```textEXPLORE(v)```and `v` is valid:```textEt+1 = Et ∪ {v}Vt+1 = Vt ∪ {v}Bt+1 = Bt - 1```Append the selected node/action to traversal history.Then obtain the eligible unvisited neighbors for the next decision.One accepted additional graph node consumes one unit of the primary traversal budget.---## 19. STOP Semantics`STOP` means that the controller judges further graph exploration unnecessary based on the current query, retrieved evidence, candidates, history, and remaining budget.Traversal must also terminate automatically if:```textBt == 0```or:```textNt is empty```Therefore termination occurs under:```textSLM_STOPORBUDGET_EXHAUSTEDORNO_CANDIDATES```Errors should use a separate termination/error status.---## 20. Budget DefinitionFor the primary experiment:> **B = maximum number of additional graph nodes that may be selected after initial seed retrieval.**Do not combine graph expansions, token usage, latency, and monetary cost into one weighted budget for the initial implementation.Primary cost:- additional graph nodes selected / successful `EXPLORE` actions.Secondary efficiency measurements:- number of SLM calls;- input tokens;- output tokens;- total tokens;- traversal depth;- inference latency;- total retrieval latency.The controller may stop before using the complete budget.For each query:```textC(q) <= B```---## 21. Reference Traversal AlgorithmConceptual pseudocode:```textINPUT:    query q    graph G    seed count k    candidate limit m    traversal budget B1. S0 ← initial_retrieve(q, k)2. E ← S0   V ← S0   H ← []   b ← B3. while b > 0:       candidates ← collect_unvisited_neighbors(E, V)       if candidates is empty:           terminate with NO_CANDIDATES       if len(candidates) > m:           candidates ← cheap_prefilter(q, candidates, m)       action ← SLM(           query=q,           evidence=E,           candidates=candidates,           history=H,           remaining_budget=b       )       if action == STOP:           terminate with SLM_STOP       if action is invalid:           apply deterministic error/fallback policy           log failure       v ← selected candidate       E ← E ∪ {v}       V ← V ∪ {v}       H ← H + [v]       b ← b - 14. If b == 0:       terminate with BUDGET_EXHAUSTED5. Return:       retrieved evidence       traversal path/history       budget used       stop reason       efficiency statistics```The exact code should adapt to SAGE's real data structures rather than forcing new ones unnecessarily.---## 22.
